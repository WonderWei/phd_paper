# 三篇论文参考文献迁入博士论文的方案

## 目标与范围

将 `ReCoW.pdf`、`MITDM.pdf` 和 `socc.pdf` **文末引用的文献**整理为博士论文可使用的 BibTeX 条目，合并到 `ref/thesis.bib`，再按博士论文正文实际论述需要插入 `\cite{...}`。本方案处理的是三篇论文的参考文献，不涉及移植论文正文、图表或实验。

三份 PDF 的文末参考文献编号分别为 ReCoW `[1]`–`[59]`、MiTDM `[1]`–`[42]`、Duet `[1]`–`[32]`，因此有 **133 条原始记录**。这是去重前的记录数，不是最终新增 BibTeX 条目数，也不是博士论文文末应显示的条目数。`ref/thesis.bib` 目前已有 197 条，需要与之一起去重。

| 来源 | 原始记录 | 主要主题 | 优先用于博士论文 |
| --- | ---: | --- | --- |
| ReCoW | 59 | 持久内存、写时复制、事务持久性、地址重映射 | 绪论的持久内存研究现状、基础章、ReCoW 章 |
| MiTDM | 42 | 解耦内存、RDMA、MVCC、版本布局与并发控制 | 绪论的远程内存与多版本研究现状、基础章、MiTDM 章 |
| Duet (`socc.pdf`) | 32 | 云原生数据库、分离式缓存、远程内存与写回 | 绪论的云原生缓存研究现状、基础章、Duet 章 |

## 模板中的引用要求

- 统一文献库：`main.tex` 使用 `\bibliographystyle{HUSTThesis}` 和 `\bibliography{ref/thesis}`。新增文献放在 `ref/thesis.bib`，不直接复制三篇 PDF 文末已排好版的参考文献文本。
- 正文引用：模板加载 `natbib` 的 `numbers,super,sort&compress` 选项。一般使用 `\cite{key}`；同一处引用多篇用 `\cite{key1,key2}`；需要行内编号时可用 `\inlinecite{key}`。PDF 中的 `[17]` 只是原论文内部编号，博士论文会自动重新编号，不能沿用。
- 中文文献：BibTeX 条目设置 `langid={chinese}` 或 `language={chinese}`。英文文献不必套用该字段。
- 数据完整性：期刊论文至少核验作者、题名、期刊、年份，并尽量补全卷、期、页码或文章号；会议论文核验作者、题名、会议正式名称、年份、页码或文章号；书籍、技术报告和网页使用相应 BibTeX 类型及其适用字段。`HUSTThesis.bst` 没有声明 `doi` 字段，不能假设写入 `doi={...}` 就会显示在最终文献表中；如学院要求显示 DOI，需要另外检查或调整样式。
- 只有正文实际使用 `\cite{...}` 的条目才会进入最终参考文献表。全部导入 `.bib` 与全部显示在文末是两件事。不要仅为凑齐原论文的全部条目而对无关文献使用 `\nocite{*}`。

## 执行步骤

### 1. 建立可追溯的来源清单

按三份 PDF 的文末编号逐条登记 `来源 PDF + 原编号 + 原始文献信息 + 拟定 BibTeX key + 核验状态`。建议后续维护 `doc/参考文献来源对照表.csv`，一条来源记录占一行；同一文献出现在多篇论文时，可以有多行来源记录，但最终只对应一个 BibTeX key。保留原编号只是为了回查 PDF，绝不把它作为博士论文中的固定编号。

### 2. 合并与去重

先用 DOI、ISBN、arXiv ID 等标识符匹配；缺少标识符时，用规范化后的**题名 + 第一作者 + 年份**比对，并人工检查会议版/期刊版、预印本/正式版是否为同一工作。先比对三篇论文之间，再比对现有 `ref/thesis.bib`。优先保留信息较完整、正式发表的版本；如两个版本确实是不同工作，应分别保留。

已发现的核对样例：ReCoW `[13]` 与 `[14]` 的题名和页码相同，疑似同一文献的两种著录；MiTDM `[2]` 与 Duet `[5]` 都是 *PolarDB Serverless*；MiTDM `[29]` 与 Duet `[22]` 都是 *LegoOS*。这些只是已识别的例子，不能据此推定最终重复数。

### 3. 核验并录入 BibTeX

优先从出版方、作者公开的 BibTeX 或权威索引获取元数据，再与 PDF 文末条目核对。PDF 文字提取可作为录入起点，不能直接当最终数据：断行、连字符、特殊字符、作者缩写、会议名称和页码容易出错。逐条确认文献类型（如 `@article`、`@inproceedings`、`@book`、`@techreport`、`@misc`），统一作者分隔符 `and`、页码范围 `--`、大小写保护和特殊字符转义。没有核实的字段留待核验，不编造 DOI、期号或页码。

为每篇独立文献分配稳定且有意义的 key，例如 `zhang2024motor`；如果现有 `.bib` 已有同一文献，复用旧 key，避免改动已有引用。新增时检查全库 key 唯一，并记录三篇 PDF 的原编号到 key 的映射。

### 4. 在博士论文中按论点使用引用

优先给 `intro.tex` 的四组国内外研究现状、`overview.tex` 的技术背景，以及 `recow.tex`、`mitdm.tex`、`duet.tex` 的问题分析、相关方案对比和实验基线补充引用。每个引用都应支撑相邻的具体事实、方法或比较，而不是把整篇论文的文献列表机械复制到章末。跨章节同一文献使用同一 key；综述中引用原始研究，实验设置引用工作负载或基线的原始来源。

建议分两层推进：先把三篇 PDF 的全部参考文献规范地录入并去重，形成可复用文献库；再根据博士论文的实际文字逐条插入引用。尚未在正文用到的条目可保留在 `.bib`，但不会出现在最终参考文献表中。

### 5. 编译与验收

使用模板现有的 `xelatex -> bibtex -> xelatex -> xelatex` 配方编译 `main.tex`。验收时检查：

1. `bibtex` 无重复 key、缺失条目和必需字段告警；正文无 `?` 引用。
2. 同一文献在博士论文中只对应一个文末条目；三份 PDF 的 133 个原编号都能在来源对照表中追溯到一个处理结论（导入、合并、待核验或不适用）。
3. 文末编号、上标引用、中文作者显示、会议/期刊名称、页码及特殊字符正确；抽查三篇论文各自的代表文献和跨论文重复文献。
4. 将编译后的文献表与学院当年的最终格式要求比对。仓库模板为非官方版本，不能仅凭 `.bst` 文件认定已满足学院全部要求。

## 交付顺序

1. 完成来源对照表与去重结果，明确唯一文献数和需要人工核验的条目。
2. 更新 `ref/thesis.bib`，保留每条来源与 BibTeX key 的对应关系。
3. 按博士论文正文完成必要引用，编译并逐页抽查文末参考文献表。

本方案阶段不修改 `.bib` 或论文正文，也不预设 133 条文献必须全部出现在最终文献表中。
